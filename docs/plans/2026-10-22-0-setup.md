# Phase 0: Project setup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An empty but working 82 Startup app: Next.js and local Supabase run, unit and database tests run, CI runs them on every pull request, and the GitHub, Vercel and Supabase projects exist.

**Architecture:** A single Next.js app (App Router, TypeScript) with Supabase for Postgres and Auth, deployed to Vercel. Local development uses the Supabase CLI. Nothing product-specific is built here; later phases add auth, events and the rest.

**Tech Stack:** Next.js (the version `create-next-app@latest` installs), TypeScript, Vitest, Supabase CLI (local stack, pgTAP tests), GitHub Actions, Vercel.

**Spec:** `docs/specs/2026-10-22-82startup-platform-design.md`

## Global Constraints

- Next.js differs from older versions: before writing Next.js code, read the relevant guide in `node_modules/next/dist/docs/` (see `AGENTS.md`).
- Never push to `main`; `main` changes only by merging a pull request.
- Database changes only through timestamped migration files.
- Secrets never in code, chat or commits. They live in Vercel and Supabase settings and the firm's password manager.
- Environments: Local = local Supabase; Preview = Preview Supabase project; Production = Production Supabase project.
- English only; UI text kept in one place.
- Every thread: one GitHub issue → one branch `<person>/<issue#>-<slug>` → one worktree `.worktrees/<issue#>-<slug>` (git-ignored).

## File Structure

- `package.json`, `tsconfig.json`, `next.config.ts`, `src/app/…` — created by `create-next-app`.
- `vitest.config.ts` — unit test configuration.
- `src/lib/smoke.test.ts` — proves the unit test runner works (removed when real tests exist).
- `supabase/config.toml`, `supabase/migrations/` — created by `supabase init`.
- `supabase/tests/smoke.test.sql` — proves `supabase test db` works (removed when real tests exist).
- `scripts/dev-env.sh` — writes `.env.local` from the running local Supabase.
- `.github/workflows/ci.yml` — lint, unit tests, build, database tests.
- `CLAUDE.md` — working rules for this project.
- `.gitignore` — adds `.worktrees/` and `.env.local`.

## Every piece of work is a thread

One GitHub Issue → one branch → one git worktree → one owner.

### Task 4: CI on pull requests

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/ci.yml`:
```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm run build
      - uses: supabase/setup-cli@v1
      - run: supabase start
      - run: npm run test:db
```

- [ ] **Step 2: Check the file is valid YAML**
