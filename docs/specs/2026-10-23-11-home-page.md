# Home page — featured and upcoming events

Issue #11. Replaces the default Next.js page at `/` with the real home page described in
`2026-10-22-82startup-platform-design.md` (Public pages). Where this document and the platform design differ, this
document wins.

## Decision (owner, 2026-10-23)

The admin screens that switch `featured` and `show_on_home` on arrive in Phase 3, so today both are `false` on every
event. Until then:

- **Upcoming** is automatic: the next 3 events that have not ended.
- **Featured** shows only events with `featured = true`. None exist yet, so the section does not appear until Phase 3
  lets an admin switch it on.
- `show_on_home` is not read in this phase. Phase 3 decides how it relates to the automatic list.

No data change and no migration is needed.

## What the page shows

1. **Intro.** The site name as the heading, one line under it (`Events and community for Korean founders, investors
   and builders.`, the text already used as the site description), and one button, **Browse events**, to `/events`.
2. **Featured events** (only when at least one qualifies). Events that are published, visible, `featured`, and not
   ended, soonest first, shown with the same card as `/events`.
3. **Upcoming events.** The next 3 events that have not ended, soonest first, same card, never repeating an event
   already shown under Featured. Below the list, a link **See all events** to `/events`. When there is no upcoming
   event: "No upcoming events yet. Check back soon."

"Not ended" means the end time, or the start time when there is no end time, is now or later (the same rule as the
Upcoming tab on `/events`). Hidden, removed-from-Luma and cancelled events never appear; the existing read rules
already guarantee that.

## How it is built

- The page reads at request time (`Suspense` + `await connection()`), never during the build, like `/events` and
  `/profile`. It uses the same cached read as `/events` (`getVisibleEvents`, tag `events`), so the hourly sync
  refreshes it too.
- `PublicEvent` and the cached read gain the `featured` column.
- A pure function picks the two lists from the events and the current time, so it can be tested without a browser.
- All text goes in `src/lib/copy.ts`.
- The template's leftover image files that only the old home page used are removed.

## Testing

Tests are written first.
- **Unit:** the picker returns featured events only when flagged, soonest first; excludes ended events; returns at most
  3 upcoming; never repeats a featured event in Upcoming; handles no events; uses the start time when there is no end
  time.
- **Browser QA (local, seeded data):** home with several events (Upcoming only), with one event flagged `featured`
  (Featured appears and is not repeated), with no events (empty message), **Browse events** and **See all events**
  links, event card opens the event page, 375px width, the header link still works.

## Out of scope

Hero artwork, member or investor sections, a sign-up call to action, the Phase 3 toggles, and anything about
`show_on_home`.

## Release

Merge, then check `/` on production. No migration, no environment variable.
